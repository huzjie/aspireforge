# aspireforge 架构

## 一句话

一个**零依赖**的「机器人技能库 + 失败复盘自改进编程智能体」参考实现，对应 NVIDIA ASPIRE 的核心思想：让编程智能体为机器人写控制程序，从失败轨迹里复盘改码，并把每一次成功的有效方法沉淀进技能库，供后续长程未见任务零样本复用。

## 四大工程件

| 组件 | 目录 | 职责 |
| --- | --- | --- |
| 技能库 | `skill/` | 内容寻址存储 + 标签/嵌入检索 + 溯源（provenance） |
| 机器人世界 | `robot/` | 任务/观测/确定性仿真/轨迹，成功信号与基准共享同一 oracle |
| 编程智能体 | `coder/` | 提示词模板 + 程序生成（检索增强） |
| 失败复盘闭环 | `reflect/` | 根因分类 → 修复 → 复测；成功后蒸馏进技能库 |

## 数据流

```
task + observation
      |
      v
 [技能库检索] --命中--> memory hit (零样本成功)
      | 未命中
      v
 [生成程序] -> [仿真执行]
      | 失败
      v
 [根因分类] -> [修复程序] -> [复测]  (最多 max_repairs 轮)
      | 成功
      v
 [蒸馏成 Skill] -> 写入技能库
```

## 为什么成功信号是可复现的

仿真与基准**共用同一个 `oracle`**：`program_correct(task_id, code)` 判定程序是否按顺序覆盖了任务所需的原语序列。mock 后端用 `boost=(skill-0.5)*2` 驱动生成保真度——skill=0.5 时 boost=0（随机基线 0.5**len），skill=1.0 时恒正确。这保证每个数字可复现、随 skill 单调。

## 零依赖策略

- YAML 读取：内置 `utils/yamlish.py` 极简解析器兜底。
- 确定性随机：`utils/stable.py` 用 `md5(key)` 种子驱动 `random.Random`。
- HTTP：`http.server` 标准库。
